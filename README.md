# Declarative Automation Bundle Template

A custom **Declarative Automation Bundles (DABs)** template for Databricks data engineering projects. Formerly called **Databricks Asset Bundles**; the repository URL is retained for existing links.

Answer seven prompts to scaffold bundle configuration, a scheduled job, a Lakeflow Spark Declarative Pipeline (SDP), a starter notebook, and an Azure DevOps pipeline example.

## Quick start

Install the modern [Databricks CLI](https://docs.databricks.com/aws/en/dev-tools/cli/install), not the legacy Python `databricks-cli` package.

Authenticate to a workspace first (the CLI requires an authenticated workspace client even for custom-template initialization):

```sh
databricks auth login --host https://YOUR-WORKSPACE --profile bundle-dev
```

From a directory where you want to create a new project:

```sh
databricks bundle init https://github.com/brianjmurray/databricks-asset-bundle-template --template-dir templates --profile bundle-dev
```

Or clone this repository and initialize from the local template root:

```sh
git clone https://github.com/brianjmurray/databricks-asset-bundle-template.git
mkdir bundle-demo
cd bundle-demo
databricks bundle init ../databricks-asset-bundle-template/templates --profile bundle-dev
```

The template root is `templates/`, which contains `databricks_template_schema.json`; `templates/template/` contains the files to generate. Optional: use the Databricks VS Code extension for development.

## Prompts

- `project_name`: bundle/project name
- `data_domain`: business domain, used as a job tag
- `data_source`: source type, used in generated notebook/resource names
- `source_name`: source system, used as the default silver schema
- `dev_environment`, `staging_environment`, `production_environment`: workspace URLs

Use simple identifier-safe values such as `DemoProject`, `Marketing`, `Datalake`, and `Salesforce`. Use non-sensitive demo inputs on camera. Placeholder workspace URLs are for scaffolding only, not validation or deployment.

## What gets generated

```text
<output>/
├── databricks.yml
├── <project_name>-pipeline.yml
├── README.md
├── resources/
│   ├── <project_name>_job.yml
│   └── <project_name>_pipeline.yml
├── scratch/
│   └── exploration.ipynb
└── src/
    └── <project_name>_<data_source>ToGold.ipynb
```

**This is a scaffold, not a ready-to-run ingestion pipeline.** The generated notebook only loads configuration values. Implement your transformations before running it. The current template creates one notebook, not separate bronze/silver/gold notebooks. `test_project/` is a separate NYC taxi example with medallion transformations and dashboard query examples; those extras are not generated by initialization.

`scratch/` is an exploration convention, not a guarantee of deployment exclusion: the bundle has no explicit sync exclusion for it.

## Environments and deployment

The targets are `dev` (default development mode), `rc` (staging, also development mode), and `prod` (production mode). Customize catalogs, schemas, permissions, workspace paths and identities for your organization. Catalogs/schemas and appropriate permissions must exist or be provisioned separately.

Authenticate to your intended workspace using a named CLI profile. From the generated bundle root, check before deploying:

```sh
databricks bundle validate -t dev --profile YOUR_PROFILE
```

Validation requires real workspace access and does not prove a pipeline will execute successfully. Deployment can create billable resources. Review the hourly job schedule before enabling production; development mode pauses triggers by default.

### Azure DevOps example (not self-contained)

The generated `*-pipeline.yml` references an external `dbx.build` repository and `templates/databricks-bundle-pipeline-template.yml`, plus `dbxDev`, `dbxStaging`, and `dbxProd` variable groups. These dependencies are **not included** here. Replace or supply them and review the working-directory/path filters before enabling CI/CD. Initialization does not configure approvals or service connections.

## Repository map

- `README.md`: documentation for this custom-template repository
- `templates/`: custom template schema and generated-file sources
- `templates/template/README.md.tmpl`: project-specific developer guide, rendered as `README.md` in each initialized bundle
- `test_project/`: separate worked NYC taxi example; replace placeholder workspace settings
- `typings/`: editor-only Spark/dbutils type hints; not pipeline implementation
- `scripts/check_structure.py`: offline JSON/notebook/template-reference checks
